# Improvements Backlog

This backlog is based on the current 1.8.0 source, POM, resources, and generated artifacts. Economy/Vault features are intentionally excluded from this backlog.

## Completed in the 1.13.0 pass

Verified by compiling the full project (all `.java` files, real `pom.xml` versions preserved) against the actual bundled `DiscordSRV-Build-1.30.5.jar` plus hand-written Bukkit/Paper API stubs, since this sandbox has no network access to Maven Central/PaperMC's repository.

- Lowered `pom.xml`'s Java target from 25 to 21 (Paper 1.21.x only requires 21; targeting 25 needlessly restricted which server JVMs could load the jar).
- Fixed a real deprecation: `MessageAction#embed(MessageEmbed)` (used by `/gcash`'s file-attached embed) → `setEmbeds(MessageEmbed)`.
- Fixed a real bug: `/purge`'s bulk-delete path declared its "done" callback complete immediately instead of waiting on the futures `purgeMessages()` actually returns.
- Fixed a real bug: see the "Make file/config persistence single-threaded" status note below.
- Removed dead code: see the "Split StatusEmbed.java into services" status note below.
- Cleaned up repository hygiene: removed `dependency-reduced-pom.xml` (stale, regenerated by the build) and 16 accumulated historical jars plus stale `generated-sources`/`generated-test-sources` under `target/` (all already covered by `.gitignore` going forward), and an empty stray `META-INF/` folder at the project root.
- Closed two Low Priority backlog items outright (PlaceholderAPI expansion, scheduled presence) — see their entries below.
- Bumped `plugin.yml`/`pom.xml` to 1.13.0 and added `PlaceholderAPI` as a `softdepend`.

## Completed in the 1.13.0 bug-fix pass (real Maven build, Paper API + DiscordSRV 1.30.5)

- **Duplicate Discord replies after reload:** the JDA prefix/button listener was never removed in `onDisable`, so every plugin reload stacked another listener. It is now tracked and unregistered.
- **`/discordstatusreload` was config-only:** it now also reloads automations and restarts every scheduled task (dashboard, presence, log purge, auto-backups) with the new intervals. `/discordstatusrestore` uses the same full reload.
- **Interval automations duplicated on reload:** `AutomationManager.load()` now cancels its previous timers first.
- **Log purge re-deleted the same page:** each batch now waits for `purgeMessages()` to finish before fetching the next page.
- **Suggestion buttons:** "Considering" and "Planned" fired `SUGGESTION_DENIED`; only Accept/Reject fire decision triggers now. `DISCORD_BUTTON` and `SERVER_SHUTDOWN` triggers are now actually dispatched.
- **`PLAYER_DEATH` automations had no player:** `PlayerDeathEvent` is not a `PlayerEvent`, so `{player}` and player actions silently did nothing.
- **Automation cooldowns** were consumed before conditions were checked (a non-first join burned the first-join cooldown); the check/take is now atomic.
- **`TRIGGER_AUTOMATION` loops** (a→b→a) now stop at a depth of 8 instead of overflowing the stack. Sounds, worlds, IDs and role fields are validated at load time.
- **Discord interaction variables** `{discord_user}`, `{discord_name}`, `{discord_guild}`, `{component_id}` are available to automations (e.g. `ASSIGN_DISCORD_ROLE` with `user: "{discord_user}"`).
- **Verification** told users the role was assigned before Discord answered; it now reports success or the real failure (role hierarchy / Manage Roles).
- **Report wizard race:** report state was shared between the async chat thread and the main thread via plain `HashMap`s; now concurrent. Expiry no longer mutates the map it iterates.
- **Menus** are identified by a custom `InventoryHolder` instead of the window title (anvil-renamed chests could impersonate them), drags into menus are blocked, and inventories are closed/reopened on the next tick.
- **`!players`** failed on servers with more than 25 players online (Discord's embed field limit); FAQ/staff embeds are capped too.
- **Leaderboard** re-read offline players' stats files inside the sort comparator and scanned ~1,000 legacy materials; values are now computed once per player.
- **Tab completion** suggested player names for `/dsnote`/`/dswatch`'s action argument; it now completes actions, players, watchlisted names and backup files.
- **`/dsnote`** no longer triggers a blocking Mojang lookup on the main thread for unknown names.
- **Audit log** writes are serialized (no interleaved lines or rotation races), newlines in entries are flattened, and writes during shutdown are synchronous.
- **ServerLoadEvent** after a Bukkit `/reload` no longer posts a "server started" embed or fires `SERVER_STARTUP`.
- Backups go through `BackupService` (create/list/prune/restore); removed unused `sendNextChangelog` and stale imports.

## High Priority

- [ ] **Split `StatusEmbed.java` into services**  
  **Category:** Refactoring · **Reason:** One class owns lifecycle, commands, listeners, persistence, scheduling, embeds, and Discord I/O.  
  **Expected impact:** Lower regression risk and easier testing.  
  **Difficulty:** High.  
  **Suggested implementation:** Extract `DiscordGateway`, `EmbedFactory`, `ReportService`, `StatsService`, `ConfigService`, `BackupService`, and listener classes while preserving the current public command behavior.

  **Status:** Small step taken: `commands/CommandRouter.java` existed fully-built but was never actually wired in (dead code). `onCommand()` now routes through it via `registerCommandHandlers()`, with identical per-command behavior. The larger extraction (embeds, Discord I/O, listeners) described above is still outstanding.

- [ ] **Add Paper and JDA integration tests**  
  **Category:** Testing · **Reason:** The repository has no tests for command registration, embeds, reports, dashboards, role verification, or configuration parsing.  
  **Expected impact:** Catch API and startup regressions before deployment.  
  **Difficulty:** High.  
  **Suggested implementation:** Add JUnit tests for pure builders, MockBukkit tests for command/listener behavior, and a mocked Discord gateway for queue/failure paths.

- [ ] **Add configuration schema versioning and migration**  
  **Category:** Configuration · **Reason:** `saveDefaultConfig()` does not merge newly introduced keys into an existing operator config.  
  **Expected impact:** Safe upgrades without manual YAML merging.  
  **Difficulty:** Medium.  
  **Suggested implementation:** Add `config-version`, migrate known versions, preserve custom values, and report migrations in the console.

  **Status:** Initial versioning and missing-default merging are now implemented; explicit historical migrations remain.

- [ ] **Replace system-scoped DiscordSRV dependency strategy**  
  **Category:** Build · **Reason:** `pom.xml` requires a local `DiscordSRV-Build-1.30.5.jar`, while DiscordSRV is not resolved reproducibly.  
  **Expected impact:** Reproducible CI and clearer runtime compatibility.  
  **Difficulty:** High.  
  **Suggested implementation:** Publish/use a controlled Maven repository or a documented dependency acquisition step, pin checksums, and test against supported DiscordSRV versions.

- [x] **Synchronize or remove `dependency-reduced-pom.xml`**  
  **Category:** Build cleanup · **Reason:** Generated metadata can drift from the main project version.  
  **Expected impact:** Prevent misleading release metadata.  
  **Difficulty:** Low.  
  **Suggested implementation:** Regenerate it during packaging or remove it from source control and ignore generated output.

  **Status:** Removed from source control (it's `.gitignore`d and regenerated by `mvn package`'s shade step); it was still present and drifted (1.9.0 vs. the actual 1.12.0) before this pass.

- [ ] **Centralize Discord error classification and retries**  
  **Category:** Reliability · **Reason:** Most `queue()` failures only log a message and do not distinguish permissions, rate limits, missing channels, or transient network errors.  
  **Expected impact:** Faster recovery and actionable troubleshooting.  
  **Difficulty:** Medium.  
  **Suggested implementation:** Wrap RestActions in a gateway with bounded exponential backoff, retry only transient failures, and log config path/channel/action on permanent failures.

- [ ] **Make file/config persistence single-threaded**  
  **Category:** Reliability · **Reason:** Audit, changelog, dashboard, and scheduled tasks can read or write Bukkit configuration from different threads.  
  **Expected impact:** Avoid races and partial config writes.  
  **Difficulty:** Medium.  
  **Suggested implementation:** Serialize state changes through the Bukkit scheduler and use atomic temporary-file replacement for YAML/log writes.

  **Status:** One confirmed instance fixed: the changelog message-edit success path (`sendUpdatedChangelog`) wrote to `FileConfiguration` and called `saveConfig()` directly from the JDA callback thread; it now hops back to the main thread first, matching the sibling `sendNewChangelog` path. The broader pattern (config reads from async dashboard/leaderboard/purge tasks) is unchanged and still applies.

## Medium Priority

- [ ] **Add real Discord thread support for suggestions**  
  **Category:** Feature · **Reason:** The current bundled JDA surface has no thread API, so suggestions only create a message and discussion prompt.  
  **Expected impact:** Keep suggestion discussion attached to its original post.  
  **Difficulty:** High.  
  **Suggested implementation:** Upgrade to a DiscordSRV/JDA version exposing thread creation, isolate it behind an adapter, and persist the thread ID with the suggestion.

- [ ] **Add slash-command options, validation, and autocomplete**  
  **Category:** API · **Reason:** Rich player commands currently require legacy `!profile <player>`/`!stats <player>` text arguments, while `/profile` is only an instruction.  
  **Expected impact:** Better Discord UX and safer input handling.  
  **Difficulty:** Medium.  
  **Suggested implementation:** Use `OptionData` for player/category arguments, autocomplete online/offline names, and share validation with text commands.

- [ ] **Persist report state and button history**  
  **Category:** Moderation · **Reason:** Report button changes are edits to a Discord message but no structured report record is stored.  
  **Expected impact:** Searchable history, reopening, audit trails, and restart resilience.  
  **Difficulty:** Medium.  
  **Suggested implementation:** Store report ID, message/channel IDs, target, reporter, status, handler, timestamps, and transitions in SQLite or a versioned YAML repository.

- [ ] **Add report timeouts and cleanup**

  **Difficulty:** Low.

  **Status:** Quit cleanup and configurable 30-minute expiration are now implemented; persisted report history remains.

- [ ] **Add startup health summary**

- [ ] **Add scheduled status dashboard tests and safe ownership recovery tests**

  **Expected impact:** Repeatable versioned artifacts and checks.

  **Suggested implementation:** Add GitHub Actions for Java 25, `mvn verify`, tests, artifact upload, and a release workflow that validates plugin/POM versions.

## Low Priority

- [x] **Add a real PlaceholderAPI expansion**  
  **Category:** API · **Reason:** The README correctly states that PlaceholderAPI is not currently supported.  
  **Expected impact:** Use plugin data in scoreboards and other server integrations.  
  **Difficulty:** Medium.  
  **Suggested implementation:** Add PlaceholderAPI as `softdepend`, register `%discordstatus_*%` values only when present, and unregister cleanly.
